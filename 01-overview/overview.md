# Overview: Infosys SP and DSE Roles

## What are these roles?

Infosys runs several distinct hiring tracks beyond the standard entry-level System Engineer (SE) role. Two of the more technical, higher-paying tracks are:

- **Specialist Programmer (SP)** — a pure coding/algorithms role. Candidates are evaluated heavily on DSA and algorithm design. Internally, SP has sub-levels (L1/L2/L3) with increasing scope and pay.
- **Digital Specialist Engineer (DSE)** — a full-stack/digital role covering modern application development, automation, analytics, and cloud-adjacent skills. Coding difficulty is generally a notch below SP, but breadth across the stack (frontend, backend, APIs, databases) matters more.

Both sit above the standard ASE (Associate Software Engineer) track and below/parallel to Infosys's "Power Programmer" hiring line.

## SP vs DSE — how to think about the difference

| Aspect | SP | DSE |
|---|---|---|
| Core focus | DSA, algorithms, competitive-programming-style problems | Full-stack development, digital tech, applied engineering |
| Coding difficulty | Higher — graph/DP-heavy problems appear more often | Moderate — more application-style problems |
| Interview emphasis | Time/space complexity, algorithmic tradeoffs | Resume projects, frameworks used, API design, DB schema choices |
| Typical fit | Strong competitive programmers, DSA-first prep | Strong project builders, full-stack exposure |

## Salary bands

Reported packages for freshers across SP levels and DSE run roughly **₹10–21 LPA**, with SP L2/L3 typically at the higher end. Exact figures vary by batch and location — treat these as directional, not guaranteed.

## Hiring stages (typical flow)

1. **Registration / eligibility check** — branch, CGPA, backlog criteria as per the official notification.
2. **Online coding assessment** — the core filter. 3 coding questions, 3 hours total, different topics and difficulty per question (see `02-syllabus-and-pattern/`).
3. **Technical interview** — DSA, OOP, SQL, and deep dives into your resume/projects.
4. **HR / behavioral round** — culture fit, situational judgment, "why Infosys," career goals.
5. **Offer** — role and level (SP L1/L2/L3 or DSE) assigned based on overall performance, not always known in advance.

## Key prep principle

Across every source used to build this repo, one point repeats: **the online coding assessment is the hardest filter**. If you clear it, the interview stage is very manageable for anyone with solid fundamentals. This means coding-round prep (Section 03) should get the majority of your prep time, not the interview-question banks.

## Hiring Pathways: Campus vs. HackWithInfy

Infosys recruits for SP and DSE roles through two primary routes:

1. **On-Campus / Infytq / Dedicated Off-Campus Hiring Drives**:
   - Organized directly with colleges or via nationwide off-campus drives.
   - Usually involves an initial screening/coding round followed directly by technical & HR interviews.

2. **HackWithInfy (National Competitive Coding Competition)**:
   - Open to all eligible engineering students across India.
   - **Round 1 (Qualifier)**: 3 coding problems in 3 hours (Easy, Medium, Hard). Top performers get direct interview calls for SP/DSE roles or qualify for Round 2.
   - **Round 2 (Grand Finale)**: Hackathon / advanced coding round for top national rankers, offering direct SP roles and cash prizes.

## Role Selection Self-Assessment Rubric

Use this checklist to decide which target role to optimize your preparation strategy for:

- **Target SP if**:
  - [ ] You regularly solve LeetCode Medium/Hard or participate in Codeforces / CodeChef contests.
  - [ ] You are comfortable formulating Dynamic Programming state transitions and Graph algorithms under time pressure.
  - [ ] You enjoy algorithmic optimization and analyzing Big-O time/space tradeoffs.

- **Target DSE if**:
  - [ ] You have built end-to-end full-stack web applications, APIs, or database-driven projects.
  - [ ] You prefer solving practical implementation problems over abstract competitive programming challenges.
  - [ ] You can confidently defend your project architecture, database schema, and technology choices in an interview.
